# Documentation

Use when a change affects information another developer, operator, or API consumer needs to rely on.

## Workflow

Inspect existing documentation and update the smallest relevant source of truth. Cover architecture, API contracts, database/migrations, environment, deployment, authentication/authorization, and business rules only when changed. Keep examples executable or clearly labeled illustrative; never put secrets or machine-specific credentials in team documentation.

Report documents updated and any documentation intentionally not changed.
