# Code review

Use for pull-request review, change review, or pre-merge inspection.

## Review scope

Inspect correctness, architecture, authorization/security, data integrity, API contracts, performance, maintainability, readability, tests, observability, UI/UX, and compatibility. Review actual diffs and surrounding code, not only summaries.

Classify findings as CRITICAL, HIGH, MEDIUM, LOW, or INFO. State the exact impact, evidence, and actionable remediation. CRITICAL/HIGH findings must be resolved before merge unless the user explicitly accepts the risk. If no findings exist, say what was inspected and any verification still not performed.
